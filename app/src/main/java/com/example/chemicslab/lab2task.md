1. Продовжіть роботу з власним проєктом, доопрацьованим у практичній
   роботі No2. Складіть (письмово, у вигляді коментаря чи окремого переліку) повний
   список основних екранів вашого застосунку — щонайменше чотири, з урахуванням
   сутностей, визначених у практичній роботі No1. Для кожного екрана зазначте його
   роль (самостійний top-level розділ чи крок усередині сценарію) та дані, які він має
   отримувати під час відкриття (за наявності).


2. Відкрийте файл `build.gradle.kts` модуля `app` і додайте залежність
   `androidx.navigation:navigation-compose` (за наявності каталогу версій — через
   відповідний alias у `libs.versions.toml`). Виконайте синхронізацію проєкту та
   переконайтеся у відсутності помилок.
3. Для кожного запланованого екрана створіть окрему composable-функцію
   (першу з них можна взяти з практичної роботи No2, доопрацювавши за потреби). На
   цьому етапі кожен екран залишається заглушкою: `Scaffold` із `TopAppBar`, що
   показує назву екрана, та мінімальний вміст у межах `innerPadding` —
   підтвердження, який саме екран зараз відображається.

4. В окремому файлі (наприклад, `AppNavigation.kt`) оголосіть composable-
   функцію верхнього рівня, яка створює `NavController` через

`rememberNavController()` та `NavHost` з обраним стартовим екраном
(`startDestination`). У лямбді `NavHost` додайте виклик `composable("route") {
ЕкранComposable(...) }` для кожного із запланованих на кроці 1 екранів, присвоївши
кожному маршруту змістовну назву.
5. Оберіть пару навігаційно суміжних екранів вашого проєкту, що природно
   утворюють патерн «список → деталі» (або подібний), і реалізуйте для нього
   типізований параметр навігації: маршрут вигляду `"details/{id}"` з оголошеним
   `navArgument("id") { type = NavType.IntType }` (або `NavType.StringType`, залежно
   від типу ідентифікатора у вашій предметній області). У відповідному екрані-

заглушці виведіть отримане значення, щоб підтвердити коректність передавання
параметра (наприклад, «Деталі елемента з id = ...»).
6. Переконайтеся, що жодна composable-функція екрана не викликає

`NavController` напряму: кожен екран має приймати навігаційні дії як параметри-
функції вищого порядку (наприклад, `onItemClick`, `onNavigateBack`), а виклики

`navController.navigate(...)` та `navController.popBackStack()` повинні бути
зосереджені виключно всередині лямбд `composable(...)` у `NavHost`.
